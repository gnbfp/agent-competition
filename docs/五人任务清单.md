# 五人任务清单（v1）

> 用途：每人只看自己那一节，加最后两节「共同规矩」「谁挡谁」。任务都写成"能验收"的样子——做完了拿命令或文件说话，不靠口头"我差不多了"。
> 配套：`docs/组长开工包.md`（队长专用）、`docs/CSV中间格式.md`、`contracts/rules.json`、各模块 `src/*/README.md`。
> 版本：2026-11-20。估时是人天，不是硬期限；做完就打勾，进度报给 P1。

## 零、所有人先做这四件事（做完才算入职）

| # | 动作 | 验收 |
|---|---|---|
| 1 | `git clone https://github.com/gnbfp/agent-competition.git` | 本地目录能打开，`ls` 看到 `contracts/ src/ tools/ docs/` |
| 2 | 装 Python 3.12.x / Git / VS Code + 4 扩展，跑 `python tools/check_env.py` | 最后一行「环境就绪，可以开始写代码。」 |
| 3 | 在 `docs/AI使用留痕.md` 加一行自己的名字 | 文件里能看到你 |
| 4 | 填《团队统一标准与环境要求》附录 D（Python 版本 + 自检结果） | 群里贴 8 PASS 截图 |

**共同规矩**：不能直推 `main`（只能开 `feature/*` 提 PR，PR 里贴 `check_env` 输出）；改 `contracts/*.schema.json` 要先在群里说；用 AI 写的代码要留痕，且你要能讲清每一行。

## 七、每个人都适用的"完成定义"（DoD）

一件事只有同时满足这五条才算完成：

1. 代码进 `feature/*` 分支，提了 PR，PR 里贴 `check_env` + `validate_contract` + `unittest` 输出
2. 有单测或至少一条可复现的手工验证记录
3. 不绕过契约：字段名、单位、枚举与 `contracts/` 一致
4. AI 生成的代码在 `docs/AI使用留痕.md` 有一行，且你能讲清每一行
5. 文档同步更新（改了行为就改文档，改了契约就升版本号）
