# CHANGELOG —— 契约变更台账

格式：`版本 | 日期 | 变更人 | 变更内容 | 影响方`
规则：只加可选字段升小版本；改类型 / 改单位 / 删字段 / 改必填升大版本，并在阶段交界处合并。

## metrics v2.0 — 2026-11-20 — P3

- 新增 `metrics.v2.schema.json`。负荷、有氧能力和恢复指标允许用 `null` 表示缺失或无法归结的数值。
- 输出记录 TRIMP 参数和逐条结果、赛绩输入、分段心率及按天的恢复量测。`capacity.estimate_range` 是已有结果的最小值和最大值，取代 v1 的区间字段。
- 指标校验按 `schema_version` 选择 v1 或 v2。v2 的 ACWR 口径差异可保留原值并给出标记。缺数据或能力估算不一致时，必须保留空的点估值。
- 原活动、计划和示例报告契约仍用 v1。P4 可以读取独立的指标 v2 文件。正式报告对 v2 的嵌入在报告生成节点处理。
- 影响方为 P3 输出、P4 后续消费和指标样例。新增可复算的模拟量测与指标 v2 样例。

### 审核整改

- 新生成的指标读取 R02 的范围校验计算用静息心率。恢复统计排除超出该范围的日量测，并保留日量测原值和复核标记。指标 v2 的字段和兼容读取范围保持不变。
- 活动 v1 仍要求填写距离。CSV 缺距离的活动会被丢弃并写明原因，显式填写的零距离仍可保存。
- 模拟 API 的指标接口增加 `?version=2.0`。校验器遇到尚未实现的 schema 关键字会明确报错。

## v1.0 — 2026-11-15 — P4（初始化）

- 首次冻结：`activity` / `metrics` / `plan` / `report` 四份 schema + 黄金样例。
- 跨字段校验 8 条（C1–C8）：activity_id 唯一、max_hr ≥ avg_hr、配速互算、ACWR 双口径、
  VO₂max 三法一致性、计划日期与休息日、每天必须挂 rule_id、依据链完整性。
- 提供 `validate_contract.py`（标准库）与 `mock_api.py`（假后端）。
- 影响方：P2 / P3 / P4 / P5 全体。
