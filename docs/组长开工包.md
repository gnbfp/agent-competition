# 组长开工包（照做就行）

> 用途：队长一个人的活，全部在这几页里。分成四块：①今天要做完的四件事 ②发群里的开工通知 ③首次站会议程 ④体育老师访谈提纲。
> 更新：2026-11-15。做完一项就在方框里打钩，进度写进 `docs/版本与标签.md`。

## 一、今天（约 1.5 小时）

### □ 1. 开分支保护（5 分钟）

GitHub → 仓库 `gnbfp/agent-competition` → Settings → Branches → Add branch protection rule：

- Branch name pattern：`main`
- 勾 `Require a pull request before merging`，Required approvals 填 `1`
- 保存

开完的效果：谁都不能直接往 `main` push，只能提 PR → 有人看过才合并。答辩时这是"团队协作规范"的证据。

### □ 2. 发开工通知（10 分钟）

复制下面第二块，改掉【】里的内容发群里。**等四个人都回「8 PASS」再往下走**，否则后面每个人都会卡在同一个坑上。

### □ 3. 导出你自己的跑步数据（40 分钟，全项目最关键的活）

只有你能干，因为它决定了整个项目的真值来源。

1. 手表 App 导出最近 **12 个月** 的跑步记录（Garmin Connect → 活动 → 导出 CSV；华为运动健康 → 我的 → 数据导出）
2. 放到 `data/raw/`（**这个目录不进 Git**，故意在 `.gitignore` 里）
3. 按 `docs/CSV中间格式.md` 转成中间格式，命名 `data/raw/me_2025_2026.csv`
4. 跑一遍验证：

```bash
python src/p2_ingest/csv_parser.py data/raw/me_2025_2026.csv -o out/activity.json
python contracts/validate_contract.py out/activity.json
```

**注意**：`data/raw/` 里可以有姓名，但**绝不能 commit**。提交前 `git status` 看一眼，看到 `data/raw/` 就是没加进 `.gitignore`。

### □ 4. 定首次站会（5 分钟）

只定一件事：**CSV 中间格式认不认**（见第三块）。别在会上讨论架构，那会开到两小时。

## 四、体育老师 / 校队教练访谈提纲（30 分钟，问三个问题）

> 目的不是让他帮你写代码，是**校准三个我们不敢自己拍板的阈值**。谈完记要点，回来改 `contracts/rules.json` 里的 `source` 字段并写清"据 XX 老师 2026-11-XX 访谈"。

### 问题 1：ACWR 你会用滚动平均还是 EWMA？

- **追问**：你实际带队员时，是看"最近 7 天 / 最近 28 天"这个简单比值，还是用指数加权的写法？两者给出不同结论时你信哪个？
- **他的回答怎么落地**：决定 R06/R07 的**主口径**。我们现在默认 EWMA 为主、滚动为对照；如果老师说都用滚动，就把结论口径换过来，并在报告里说明"本校教练实践"。
- **记录位置**：`rules.json` → R05/R06/R07 的 `source` 追加一句实践来源。

### 问题 2：TRIMP 的男女系数你认哪套？静息心率怎么取？

- **追问**：Banister 那套 0.64/1.92（男）、0.86/1.67（女）你认不认？静息心率是早上醒来躺着测，还是手表给的"夜间静息心率"？用哪个算 ΔHR%？
- **他的回答怎么落地**：决定 R04 的系数版本与静息心率取值定义（写进 `metrics.json` 的字段说明）。这一条直接影响所有负荷数字，必须问。
- **记录位置**：`rules.json` → R04 的 `clause` 与 `notes`。

### 问题 3：一份训练计划"合理"，你看哪几条？

- **追问**：给你一份 7 天计划，你最先看什么？（总量、强度分布、长距离、休息日？）什么情况你直接说"这计划不行"？
- **他的回答怎么落地**：用来补 R08/R09/R10 的阈值，以及 L5 专家评审的打分维度（现在写的是"合理性 1–5 分"，可以细化为 3 个维度）。
- **记录位置**：`rules.json` → R08/R09/R10；`docs/项目计划书-v0.1.md` → 第六节 L5。

## 六、三个坑（照我踩过的说）

1. **只写文档不写规则库**：文档漂亮但 `rules.json` 是空的，等于项目没有内核。规则库是 P1 的第一优先级。
2. **活全堆自己身上**：队长写得越多，队友越没事干，答辩时"这部分谁做的"答不上来。宁可让队友慢一点，也要让每个人都有可指认的模块。
3. **数据迟迟不导**：L1 回测做不了，整个"验证"章节就是空的，评委一问就现形。**今天导。**
