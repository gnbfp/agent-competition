规则内容

3.6 可回溯标签与回滚（写错了能退回去）

改仓库必须留"路标"：每个阶段结束、每次契约变更，都要打一个 Git 标签（tag）。没有标签，出事时只能靠记 commit sha，五个人一起推的时候基本等于不可回溯。

四类标签（格式固定，不许自创）：

类型格式什么时候打例
阶段交付stage-<N>每个阶段结束（验收通过当天）stage-1、stage-3
契约变更contract-v<X.Y>schema 改完并通知全员之后contract-v1.1
仓库/文档快照snap-<主题>-v<X.Y>大改文档、换结构snap-standards-v1.2
对外提交版submit-<YYYYMMDD>交初赛材料、决赛前submit-20261201

怎么打（由 1 个人执行，别五个人各打各的）：

git tag -a stage-1 -m "阶段一：契约冻结 v1.0，能读到一份真实数据"   # -a 带注释，必须有
git push origin stage-1        # 推单个标签
git push origin --tags         # 或一次推全部标签

标签信息必须写三行（git show stage-1 时能看到，这就是回溯的凭证）：

这版能做什么：契约冻结，P2 能解析样例 CSV
已知问题：暂不支持 .fit 导出
谁验过：P4 跑过 check_env 8 PASS，P1 复看过协议

回滚三招（按场景选，别乱用）：

场景命令说明
撤销一次已推送的提交git revert <sha>生成一条反向提交，历史完整保留，最安全，优先用这个
只把某个文件恢复到标签版本git checkout stage-1 -- contracts/report.schema.json局部回滚，不动别人代码
自己分支还没推送，想扔掉最后一次提交git reset --hard HEAD~1仅限未推送，推过就别用

绝对禁止：对 main 或别人的分支执行 git push --force；对已经推送的公共提交做 rebase 改写历史——这会让其他人本地仓库和远端对不上，是全队级别的灾难。

台账：每打一次标签，在 docs/版本与标签.md 记一行（tag / 日期 / commit 前 7 位 / 这版内容 / 谁打的），这样不用懂 Git 的人也能查。

3.7 每个 PR 必须写清四件事（模板已进仓库）

.github/pull_request_template.md 已放进仓库，开 PR 时自动出现，照填即可：

  1. 改了哪个契约字段（没有就写"无"）；
  2. 跑了哪条校验命令、结果如何（贴 check_env 或 validate_contract.py 的输出）；
  3. 界面改动贴截图；
  4. 若含 AI 生成代码，链接到 docs/AI使用留痕.md 的对应行。

四、代码规范

4.1 Python 十条（可逐条检查）

  1. 遵守 PEP 8；行长 ≤ 100；4 空格缩进；不许 Tab。
  2. 每个函数 ≤ 50 行；超过就拆。
  3. 所有公开函数写类型注解和一句话 docstring（说清参数与返回）。
  4. 模块顶部统一 from __future__ import annotations。
  5. 变量、函数、文件用 snake_case；类用 PascalCase；常量全大写。
  6. 禁止裸 except:；捕获具体异常；异常里带上文（哪个文件、哪一行、什么值）。
  7. 库代码用 logging，不用 print；命令行脚本可以用 print。
  8. 不许留无主 TODO：写成 TODO(P3): 处理跨零点 这种带责任人的。
  9. 数值边界必须显式处理：除零、空列表、None、负值各一行防御。
  10. 一个文件只干一件事：解析的不管计算，计算的不管渲染。

4.2 命名与单位（与契约一致）

类型后缀示例说明
时长_sduration_s秒，整数
距离_mdistance_m米，整数
配速_s_per_kmpace_s_per_km6'00" = 360
心率_bpmavg_hr_bpm次/分，整数
百分比_pctratio_pct0–100
比率/指数_ratioacwr_ratio小数，保留 2 位
日期—dateYYYY-MM-DD
时间戳—started_atISO8601 带 +08:00

禁止命名：data、info、tmp、res、d1、a、x2。看不懂的命名等于没命名。

4.3 前端 JavaScript 六条

  1. 原生 ES module（<script type="module">），不引框架、不引 CDN，离线必须能跑。
  2. 不自己算指标：ACWR、TRIMP、VO₂max 一律从 report.json 读，页面只负责显示。
  3. 渲染集中在一个 render.js，禁止在事件回调里直接拼大段 HTML。
  4. 数据缺失显示「数据不足」，不许显示 0（0 会被误读为真实测量值）。
  5. 网络失败给明确提示，不许白屏。
  6. 图表用原生 SVG 或 Canvas 手绘，不引图表库。

4.4 时间与时区

存储一律 ISO8601 带偏移（2026-11-14T07:30:00+08:00），界面显示本地时间并标注 +08:00。
跨零点跑步（如 23:50 开始）归属开始日期，这条写进契约 C 系列校验里。

4.5 错误处理与日志

  • 出错时先落日志再抛异常，日志里带 activity_id 或文件路径，方便定位。
  • 不许把异常吞掉后返回一个"看起来正常"的假值——这是本项目最危险的 bug 类型（会让报告给出错误结论）。
  • 日志级别：INFO 正常流程，WARNING 数据可疑但不致命，ERROR 无法继续。

4.6 代码审查看什么（reviewer 五条）

  1. 有没有绕过契约（字段名、单位、枚举是否与 schema 一致）；
  2. 有没有自己造一套算法（同类指标是否与 P3 的实现重复）；
  3. 边界处理（空数据、缺失值、非法值）；
  4. 有没有测试或至少一条手动验证记录；
  5. 是否可解释——看不懂就直接问，问不明白就打回。

  1. 删姓名、手机号、设备序列号；
  2. 删 GPS 轨迹与起终点位置（本项目不需要位置）；

六、AI 使用规范（所有队员强制）

这一节是本文件最重要的一节。用了 AI 写的东西，责任仍然是写它的人。

6.1 三条总原则

  1. AI 是工具，不是作者：它出的是草稿，最终解释权与责任在你。
  2. AI 产出默认有错：尤其名字、单位、阈值、引用——它最爱在这些地方编得像真的。
  3. 解释不了就不提交：答辩现场评审会让你指着某一行问"这里为什么这样写"。

6.2 三档清单

档位可以用来做要求
绿：随便用写样板代码、正则、重命名、翻译、解释报错、生成测试样例、文档初稿、PPT 大纲自己读一遍即可
黄：必须逐行审 + 留痕规则判定逻辑、阈值与公式、契约字段定义、数据管道、报告文案读懂每一行 → 按本文件改风格 → 跑测试 → 填留痕
红：禁止见 6.3 六条直接打回

6.3 六条禁止（违反即打回）

  1. 禁止用 AI 生成或"回忆"文献、标准条款、数字依据。

本项目报告里每个结论都要挂 rule_id 与依据出处（契约 C8 会检查）。AI 编一条 GB/T 编号，答辩当场被问"第几条"就崩。
正确做法：AI 可以帮你解释你手上有原文的条款，不能帮你产生条款。

  1. 禁止把 schema / 契约文件整体丢给 AI 让它"顺手改"。

字段由人定（P4 + 消费方确认），AI 只能写实现。

  1. 禁止把真实姓名、GPS、健康原始数据贴进公共 AI。
  2. 禁止提交自己看不懂的代码（包括"它跑通了我就交了"）。
  3. 禁止用 AI 编的数据充当验证数据。

模拟数据必须标注"模拟"，并单独存放；验证章节里写清哪部分是模拟、哪部分是真跑。

  1. 禁止用"我觉得能跑"代替测试。AI 说"这段应该没问题"不算验证。

6.4 留痕制度

所有 AI 产出且进入仓库的代码或文档，在 docs/AI使用留痕.md 追加一行：

日期谁文件AI让它做什么我改了什么怎么验证的
11-15P2csv_parser.pyDeepSeek写配速解析补非法值兜底、改抛异常单测+5 条边界手测
  • 「我改了什么」写"没改"要特别小心——没审的 AI 代码最容易在答辩翻车。
  • 「怎么验证的」必须是一条能复现的命令或操作。

6.5 AI 生成代码的验收五步

步骤动作不合格的表现
1 读懂能用自己的话讲清这段在干什么只能说"AI 说这样写"
2 对齐字段名、单位、枚举、日志方式改成本项目规范出现 heart_rate、print、critical 这类自造词
3 跑测试check_env + 该模块测试 + 手工塞边界值只跑了一遍正常路径
4 边界空数据、缺失、非法值、跨零点各试一次"这种情况不会出现"
5 留痕填 docs/AI使用留痕.md提交里没有任何说明

6.6 提问模板（照这个结构问，返工少一半）

【项目】大学生智能体比赛作品：跑步训练闭环助手，Python 3.12，只用标准库。
【约束】字段名与单位必须与下面的契约片段一致；不许引入第三方库；
        不许编造标准编号或文献；输出只要代码，不要解释性废话。
【契约片段】（粘贴 contracts 里相关的 properties 部分）
【任务】实现 xxx，输入 yyy，输出 zzz。
【边界】空列表、缺失值、非法值分别怎么处理，请在代码里体现。

6.7 AI 与规范的冲突处理

常见冲突处理
AI 起了别的字段名（heart_rate）改成契约名（avg_hr_bpm）
AI 用 print 调试改成 logging，调试完删掉
AI 给一个"看起来合理"的阈值（如"心率超 180 就危险"）阈值必须能指到依据（ACSM 或队内约定），指不到就不用
AI 自造枚举值（critical）只用契约里的 low/medium/high
AI 生成的注释是英文或空话改成中文，说明"为什么"

总原则：契约与本文件优先于 AI 的任何建议。

6.8 用 AI 写文档与 PPT 的四条

  1. 数字一律来自 report.json 或实际测跑结果，不许让 AI"估一个"。
  2. 引用必须有可回查出处（作者、年份、期刊/标准号），且自己查过原文摘要。
  3. 不许整段照搬 AI 文本——读一遍，用自己的话重写，否则答辩一问细节就露。
  4. PPT 里的图表必须能指出数据来源文件，禁止"示意图凑数"。
