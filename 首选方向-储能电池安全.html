首选方向：锂电池储能安全「风险核查 + 热失控前兆识别」助手

面向赛道三「AI＋跨学科融合创新」
一句话：输入一座储能舱/电池测试间的运行数据与现场检查记录，输出"哪一项不符合规程、哪一颗电芯出现热失控前兆、依据哪条标准、下一步该做什么"。
为什么选它：它同时踩中常州大学三个一级博士点里的两个（安全科学与工程、材料科学与工程），踩中常州 8500 亿新能源产业，而且有公开的国家标准和公开的事故调查报告可以做验证——这三点凑齐的方向，几乎没有第二个。

一、为什么说它"专业性强"

判断一个 AI+学科方向专不专业，看三件事：专业内核能不能讲出机理、判断依据是不是可查的硬条款、效果能不能用真实事件检验。 这个方向三样都齐。

1）学科上，它正好落在本校最强的两个博士点交集
常州大学只有三个一级学科博士点：材料科学与工程、安全科学与工程、石油与天然气工程。储能电池安全 = 材料/电化学（电池本体）＋ 安全工程（事故链、防护、应急）。化学、工程、材料三个 ESI 学科均进全球前 1%，化工/材料/安全同为本省优势学科。找指导老师、找真实场景、答辩时挂学科，都不缺。

2）产业上，常州是全国的电池重镇
2025 年常州新能源产业规模突破 8500 亿元，动力电池产业链完整度 97%。储能是把动力电池技术往电力系统搬，本地企业、园区、电站案例都够用——"落地应用前景 20 分"这一项，别人要编，你有素材。

3）验证上，有公开标准 + 公开事故调查报告

  • GB/T 36276-2023《电力储能用锂离子电池》
  • GB/T 42288-2022《电化学储能电站安全规程》
  • GB 51048《电化学储能电站设计规范》
  • UL 9540A（热失控扩散测试方法，国际通用）
  • 北京丰台"4·16"储能电站火灾事故调查报告（2021 年，致 3 人死亡，磷酸铁锂储能电站）——时序、原因、责任链条全部公开，这就是你最硬的"标准答案"

有了这四类东西，"专业性"就不是形容词，是能摊在桌面上的东西。

二、专业内核：热失控到底是怎么发生的

这一段是整个作品的灵魂。评委（尤其是安全、材料方向的老师）会盯着你讲不讲得清机理。

锂离子电池热失控是链式反应，不是"温度高了就着火"：

  1. SEI 膜分解（约 80–120℃）：负极表面保护层破裂，负极直接接触电解液
  2. 负极—电解液反应放热，温度继续爬升
  3. 隔膜收缩/熔断（约 130–160℃）：正负极直接接触，内短路
  4. 正极分解并释放氧气（约 200℃ 以上）：电池自带氧化剂，所以不需要外界空气也能持续燃烧
  5. 电解液气化燃烧，产气（H₂、CO、VOC、HF 等）
  6. 热失控在模组内传播：一颗电芯烤热邻居，整舱连锁

由此推出的关键结论（这是专业判断和业余判断的分水岭）：

  • 单看温度没意义，要看温升速率 dT/dt。 正常充放电温度波动平缓，热失控前兆是曲线突然抬高斜率。
  • 要联合看电压。 内短路往往先表现为电压异常跌落或充电末端电压抬不起来。
  • 要看清一致性。 簇内单体电压离散度（ΔV）持续扩大，比"某一颗 SOH 低"危险得多——那是内短路或连接件失效的典型前兆。
  • 要看气体。 H₂/CO/VOC 提前于明火出现，是储能舱最有效的早期信号。
  • 要看工况。 低温快充易析锂（锂枝晶→刺穿隔膜），所以"低温 + 大电流 + 高 SOC"这个组合本身就带风险权重。

老化与安全的耦合（材料/电化学知识在这一步进来）：

  • 库仑效率（CE）长期低于 99.5%–99.9% → 析锂嫌疑
  • 充电末端电压平台抬升、dQ/dV 峰位偏移 → 副反应/相变异常
  • 容量衰减是"慢变量"，安全风险多是"一致性和内短路"这两个快变量

把上面这些写成规则，就是专家经验的可执行版本；这也是赛道三要求"专业知识怎样影响处理流程和结果质量"的直接答案。

三、AI 在这一步做什么（做对了才不是套壳）

环节AI 的具体职责没有 AI 也能做吗
数据接入把 BMS 曲线、巡检表、消防台账、设计参数抽成统一字段结构可以但极慢，且人工易错
特征计算dT/dt、ΔV 离散度、CE 滑窗均值、dQ/dV 曲线、SOH 轨迹可以做，AI 负责自动化
规则推理把机理判据做成"条件组合 + 时序逻辑"，输出风险项可以，但规模上不去
条款检索命中风险后回查标准条款，给出条款号与原文人工翻标准很慢，这是刚需
事故复盘用历史事故时序自动回放，检查系统是否提前给出对应风险项手工做不可行
报告生成分级风险清单 + 依据 + 处置 + 复查项可以，但一致性差

定位要说清楚：AI 是"抽取、计算、检索、解释"的放大器，专业规则是主角。 这样写既符合赛道三的原意，也避免评委一句"这就是个套壳大模型"。

但"做成什么形态才算智能体、而不是一条流水线"，是这个方向最容易被扣分的地方 —— 见第十二节。

四、输入与输出

输入（第一版）

  1. 一段 BMS 运行数据（时间、单体电压、温度、电流、SOC）
  2. 一张现场检查表（消防设施、通风、间距、灭火介质、告警配置、应急预案）
  3. 场景说明（储能舱 / 实验室电池测试间 / 电池仓储，三选一）

输出

  1. 风险清单：风险项 + 等级（高危/需整改/合规）+ 触发数据片段
  2. 标准依据：条款号 + 原文摘录（可点击定位）
  3. 热失控前兆提示：哪一簇、哪一颗、什么特征、置信度
  4. 处置建议：降功率/停机/隔离/复测/更换/加强监测，附复查项
  5. 待复核标记：超出规则库的情形明确写"需专业人员确认"，绝不硬编结论

判据示例（数值仅为示意，正式版本必须按标准与厂家参数核定）：

  • 单体 dT/dt > 1℃/min，且同簇最大温差 > 5℃ → 高危，热失控前兆
  • 簇内 ΔV > 200 mV 且连续 3 个采样点单调扩大 → 高危，内短路/连接失效嫌疑
  • CE 连续 5 个循环 < 99.5%，且充电末端电压平台抬升 → 需整改，析锂嫌疑
  • 气体探测 H₂ 或 CO 或 VOC 任一超阈值 → 高危，立即停机并启动应急
  • 储能舱灭火介质与电池类型不匹配 / 无可燃气体探测 → 规程不符，限期整改
  • 电池舱与相邻建筑防火间距不足 → 规程不符，依据设计规范条款

这张表就是你的"专业壁垒"：一张 30–40 条判据、每条都挂标准条款的表，比任何模型指标都能说服评委。

六、数据与验证（决定完成度 30 分）

数据来源

  • 电池老化/循环数据：NASA PCoE、MIT-Stanford（Severson，124 只商用电芯）、Oxford Battery Degradation——公开可下载，用来验证 CE、dQ/dV、SOH 这些特征算法
  • 事故案例：北京丰台"4·16"事故调查报告（公开全文）——用于时序复盘
  • 标准条款：GB/T 36276-2023、GB/T 42288-2022、GB 51048、UL 9540A
  • 现场检查表：本校实验室/本地企业，自己设计（这本身是专业工作）

验证方法（三件套）

  1. 专家标注 gold set：请安全工程/材料方向老师对 20 个场景标注"应判风险项 + 等级" → 报漏报率、误报率、条款引用正确率
  2. 事故时序复盘：把丰台事故的关键节点做成时间轴，检查系统在 T-30min / T-10min 等节点是否给出了对应风险项。这条最有说服力，也最容易做成演示视频的高潮
  3. 引用可定位：随机抽 20 条引用，逐条对照标准原文，算引用正确率（防 AI 编造条款）

七、第一版边界（4 周能做完）

  • 只做一个场景：储能舱（或实验室电池测试间，二选一，别贪）
  • 只做一类数据：BMS 电压/温度/电流 + 现场检查表（不做气体探测硬件，用模拟数据）
  • 只做 30–40 条判据、3 份标准
  • 只做一个事故复盘（丰台）
  • 明确不做：不预测"还剩多少天热失控"，不做硬件，不做电池选型推荐

明确的责任边界：辅助核查与前置预警工具，不替代消防验收与安全评价，最终判断由持证人员签署。

十一、答辩三个必答题（提前背好）

Q1：这和"接个大模型做问答"有什么区别？
A：我们的核心是那张挂在标准条款上的判据表。模型只负责抽取字段、跑计算、回查条款；判断逻辑是领域专家写的、可逐条审查的。演示时我会先给你看判据表，再看输出。

Q2：你怎么证明你的判断是对的？
A：三重验证——专家标注 20 个场景算漏报/误报；用丰台事故调查报告的时序回放，看系统能否在关键节点前给出对应风险项；引用条款逐条对照原文算正确率。三个失败案例我们也会展示。

Q3：这东西真有人用吗？
A：本校电池实验室和本地储能运维都需要"查规程、看前兆"的工具，我们已经访谈了 X 位老师（写进计划书），他们目前是翻标准 + 靠经验。

十二、它算不算"智能体"？（形态设计，重要）

先说结论：按第三～七节那样实现，它只是一条"规则驱动的分析流水线"，严格说不算 agent。 这是本方向最大的真实风险——你参加的是智能体大赛，评委很可能直接问："你的 agent 在哪？"所以必须在设计阶段就把形态补上，而不是等答辩被问住。

判断标准：四条

#agent 的特征流水线的样子要做到
1自主决定下一步做什么固定 DAG，顺序写死根据检查结果决定下一步（缺数据就去要、查不到就换检索路径）
2调用外部工具，且有明确工具契约内部函数调用，无契约6–8 个注册工具，各有入参、出参、失败语义
3观察结果并调整（失败重试、换路径、降级）出错就中断失败 → 换工具/换参数/降级 → 记录原因
4有目标与状态（多轮、可中断、可交接）无状态场景状态对象 + 判据覆盖度 + 待办清单

一句话区分：流水线是"我把步骤排好了，你照着跑"；agent 是"我给你目标，你自己决定跑哪几步、跑完自查还有没有漏"。

具体改法：一个"核查型 agent"的循环

目标：对场景 S 给出可复核的安全风险结论与整改清单（而不是"把流程跑完"）。

工具集（每个都要有名字、入参、失败语义）：

工具作用失败时怎么办
load_bms读 BMS 曲线并做完整性校验缺字段 → 返回缺失清单，触发追问
calc_featuresdT/dt、ΔV 离散度、CE 滑窗、dQ/dV、SOH 轨迹采样不足 → 降级为"趋势不可判"
retrieve_clause按风险类型检索标准条款无命中 → 换同义词/上位标准重试，仍无 → 标"无依据"
match_rules用判据表匹配风险项数据不全 → 输出"待复核"，不硬判
replay_timeline事故/工况时序回放时间轴不齐 → 报对齐缺口
ask_human向运维/老师追问缺失信息超时 → 走降级路径并标注来源
write_report生成分级报告—
schedule_recheck生成复查任务与触发条件—

主循环 Plan → Act → Observe → Self-check

  1. Plan：读场景说明，列出本次应覆盖的风险类型（热失控前兆 / 内短路 / 析锂 / 一致性劣化 / 规程符合性 / 消防配置）
  2. Act：按需调用工具，不是全调一遍
  3. Observe：逐条记录每条判据的状态——已判 / 数据不足 / 无依据
  4. Self-check（关键）：算判据覆盖度——应检查的判据里有多少条已给出结论？未覆盖的必须回到 1 或调 ask_human 处理
  5. 循环到覆盖度达标，或明确列出"无法判定项 + 原因"，才允许出报告

演示时必须能看见的三处 agent 行为

  1. 缺数据会主动追问："当前缺少可燃气体探测数据，气体类 6 条判据无法判定，是否补充？"——而不是静默跳过
  2. 查不到会换路径：条款检索无命中时换同义词表/上位标准，两次都失败才标"无依据"
  3. 出报告前会自查：报告生成后跑一次依据覆盖率检查，覆盖不足就打回重做

再给评委做一个对照演示（很省力但很有效）：同一份输入，让"固定流水线版"和"agent 版"各跑一遍，流水线静默跳过了缺数据的判据，agent 停下来追问了 —— 一次就把"你为什么是智能体"讲完了。

别做的事（一眼假）

  • 为了"像 agent"硬加三个 agent 互相辩论、投票 —— 评委看得出来是表演，反而扣分
  • 让 agent 自己生成判据（专业规则必须由人写、可审查，这是赛道三的立身之本）
  • 全自动无人值守（安全场景必须保留人工确认闸门，这反而是加分项）

赛道怎么报

主线仍是赛道三（创新点＝专业知识如何影响流程与结果质量）。但你的形态天然满足赛道二的"多步骤＋工具协同＋结果校验"，材料里可以写一句"以智能体形态实现专业规则的调度与自校验"——两边都占优，但别改报赛道二：那里比的是工具编排的创新性，你的优势不在这儿。

十三、学生可行性：难在哪、怎么砍到能做

先给答案：如果按前面写的"完整版"做，对本科生偏难；砍成"学生版"完全可行，但有一个前提——队里必须有一个安全工程/材料/电化学背景的人。 卡点不在写代码，在"判据站不站得住"。

五个难度维度

维度难度真实卡点能不能绕
专业规则高判据阈值从哪来、是否符合标准不能绕。没有专业队友，规则表就是抄的，答辩一问就崩
数据中高真实 BMS 数据、储能舱现场能绕：公开数据集 + 自造模拟数据

结论：写代码不是最难的，拿到"能站住脚的判据"才是。 如果队里没有专业背景的人，这条不要硬上——不是技术做不出来，是答辩一问"这个阈值凭什么是这个值"就穿。

学生版具体怎么砍（八刀）

  1. 数据不用真的：用 Severson/NASA 公开数据做特征验证，再写一个"模拟储能舱"生成器（电压温度曲线 + 注入 3 种异常），演示可控；材料里诚实标注"模拟数据"——这比拿不到数据硬编强得多
  2. 场景只做一个：电池测试间，不做整舱，不做电站
  3. 判据只写 18 条：覆盖 6 类风险（热失控前兆 / 内短路 / 析锂 / 一致性 / 规程 / 消防），每条挂 1 条标准条款
  4. 标准只摘 15 条：三份标准各取 5 条最相关条款，局部摘录并注明条款号，不追求全文覆盖
  5. 不需要训练模型：特征计算 + 规则匹配 + 条款检索 + 解释生成就够；"AI"体现在抽取、检索、自查、解释，而不是训个网络
  6. 单 agent + 6 个工具 + 1 轮自查：不搞多 agent 协作
  7. 复盘只做 6 个节点：丰台事故取关键时间点，不追分钟级精度
  8. 验证只要 10 个场景：老师标注 10 个即可，报漏报/误报 + 3 个失败案例（诚实展示失败反而加分）

一句话建议

做小做透，比做大做崩强得多。 评分表里"完成度与技术实现"占 30 分：一个只覆盖 18 条判据、但每条都能说清来源、能现场演示、有失败案例分析的作品，比一个"看起来全覆盖、一问来源就卡住"的作品分数高得多。评委看的是你说得清多少，不是你画了多大。
