# P2 导入适配说明（原始导出 → 中间格式）

> 一句话：**各家手表导出的格式都不一样，但进入系统的只有一种 CSV。**
> 本文档说明 P2 的适配器怎么把 Garmin / 华为 的导出转成 `docs/CSV中间格式.md` 规定的那 13 列。
> 它不改变契约——中间格式的字段与规则仍以 `docs/CSV中间格式.md` 为唯一真源。

## 一、两段流水线

```
手表/App 原始导出 CSV          中间格式 CSV                  契约数据
data/raw/xxx.csv  ──适配─▶  out/<名字>_middle.csv  ──校验─▶  out/activity.json
                format_adapters.py          csv_parser.py
```

| 步骤 | 谁干 | 只管什么 |
|---|---|---|
| 适配 | `src/p2_ingest/format_adapters.py` | 列名映射、单位归一、文本清理 |
| 校验入库 | `src/p2_ingest/csv_parser.py` | 缺字段丢行、心率异常旁路 R02、写 JSON |
| 串起来 | `src/p2_ingest/import_export.py` | 识别格式、落中间 CSV、调用校验入库 |

**为什么拆两段**：适配器不判断"这行能不能入库"，避免 P2 出现第二套校验规则。中间 CSV 留在
`out/` 里，P1 能目视核对，出问题也能只重跑其中一段。

## 二、支持哪些格式

| 格式名 | 覆盖的导出 | 识别特征（表头） |
|---|---|---|
| `garmin` | Garmin Connect 导出 CSV（英文或中文界面） | `Activity Type` `Date` `Distance` `Time` `Avg HR` |
| `huawei` | 华为运动健康 / Keep / 悦跑圈 的摘要导出 | `运动类型` `开始时间` `时长` `距离` |

不确定格式时先让它自己猜；猜错就用 `--from` 强制指定。

```bash
python src/p2_ingest/import_export.py data/raw/garmin.csv --list-formats
python src/p2_ingest/import_export.py data/raw/garmin.csv -o out/garmin/activity.json
python src/p2_ingest/import_export.py data/raw/huawei.csv --from huawei -o out/huawei/activity.json
```

输出文件名**必须以 `activity` 开头**，否则 `contracts/validate_contract.py` 认不出该用哪份 schema
（脚本会提示，但不会替你改名）。

两条导入命令都先尝试 UTF-8，兼容 UTF-8 BOM，解码失败时尝试 GBK。生成的 JSON 和中间 CSV 仍使用 UTF-8 无 BOM。仓库样例 CSV 也用 UTF-8 无 BOM，`tools/check_env.py` 会检查。它跳过 `data/raw/` 和 `out/`。

每次导入会在活动 JSON 的同一目录生成 `data_check.md`，记录输入编码、入库与丢弃数量、缺失字段、丢弃原因和 R02 旁路原因。生成的位置取决于 `-o`。多次导入用不同输出目录即可保留各自的报告。旁路原始记录保存在当地的 `rejected.json`，随 `out/` 留在本地。

## 三、列映射

左边是常见表头写法，右边是中间格式字段。表头里的空格、大小写、括号单位都会被忽略。

| 中间格式字段 | 认得的表头 |
|---|---|
| `date` / `start_time` | `Date` `日期` `运动日期` `开始时间` `Start Time` |
| `sport` | `Activity Type` `运动类型` `活动类型` |
| `duration_s` | `Time` `时长` `运动时长` `用时` `时间` |
| `distance_m` | `Distance` `距离` `里程` |
| `avg_hr` / `max_hr` | `Avg HR` `平均心率` / `Max HR` `最大心率` |
| `elevation_gain_m` | `Elev Gain` `爬升` `累计爬升` `总爬升` |
| `avg_pace_s_per_km` | `Avg Pace` `平均配速` `配速` |
| `rpe` / `sleep_h` / `pain` | `RPE` `主观疲劳度` / `睡眠` / `疼痛` |

认不出的列**直接忽略**（Garmin 的 `Calories`、`Best Pace`、`卡路里` 都不进中间格式）；
必需的三列 `date` / `sport` / `duration_s` 缺任意一个，整份文件直接报错退出，不会产出半成品。

## 四、单位与取值规则

| 项目 | 规则 |
|---|---|
| 距离 | 默认按 **公里**，表头写了 `(m)` `(米)` 就按米；统一输出米 |
| 时长 | 认 `1:02:03`、`48:00`、`2880`、`48分`、`1小时2分`；统一输出秒 |
| 配速 | 认 `6:00`、`6'00"`、`360`。值带 `/mi` 或表头声明 `min/mi` 时，从每英里换算成每公里。纯数字配速先按表头解释，若与跑步距离和时长差异大，且按秒解释能对上，才采用秒值并记录警告。统一输出秒/公里 |
| 心率 | 认 `152`、`152 bpm`；**0 视为缺失**（设备没记录，不能让 0 拉垮均值） |
| 缺失 | 空、`-`、`—`、`N/A`、`无` 一律当缺失，输出空串；**绝不写 0** |
| 距离 0 | 显式填 0 时保留。空白距离会使整行丢弃，体检报告记录原因。 |
| 运动类型 | 按关键字识别（跑→run、骑→bike、游→swim、力量→strength、走/徒步→other）；认不出的留空，由下游丢行并说明 |
| 时区 | 日期时间里的 `+08:00` 只做识别、不做换算，按本地时间（Asia/Shanghai）落库 |

单行某个值解析失败**不会中断整份文件**：记一条警告、该字段按缺失处理，再由 `csv_parser` 决定
这行是丢弃还是入库。无穷大等非有限数值也按字段异常处理。警告会打印到命令行。

## 五、加一种新格式（三步）

1. 在 `ADAPTER_SPECS` 里加一条：`label`、`source_id`（必须是 `contracts/activity.schema.json` 的
   `source` 枚举值）、`signature`（3–5 个有辨识度的表头）、`distance_unit`；
2. 表头别名不够就往 `_ALIASES` 里补（键要写成"去掉空白、全小写"的形式）；
3. 在 `data/sample/` 放一份脱敏样例，在 `tests/test_format_adapters.py` 加一组用例。

不用改 `csv_parser.py`——校验规则全队只有一套。

## 六、样例数据说明

`data/sample/garmin_export_sample.csv` 与 `data/sample/huawei_export_sample.csv`
**是为验证解析逻辑人工构造的模拟数据**（依据《团队统一标准与环境要求》6.3-5：模拟数据必须标注）。
它们只用来验证"格式能不能转对"，不能当作验证章节里的实验数据；

## 七、自检命令

```bash
python -m unittest discover -s tests -v
python src/p2_ingest/import_export.py data/sample/garmin_export_sample.csv -o out/activity.json
python contracts/validate_contract.py out/activity.json       # 必须 PASS
```

## 八、生成脱敏演示数据

```bash
python src/p2_ingest/anonymize.py out/activity.json -o out/activity_anonymized.json --athlete anon_01 --denylist data/raw/private_terms.txt
python contracts/validate_contract.py out/activity_anonymized.json
```

工具生成新的活动 JSON，只保留允许的运动字段和数值指标。日期平移到演示周并保留星期和日期间隔，活动 ID 重新生成，精确时间、主诉原文和非允许字段会被移除。禁止词清单每行写一个姓名或定位词，保持在本地 `data/raw/`。若直接输出到 `data/sample/`，工具要求提供非空清单，并在自检命中时停在写入前。
