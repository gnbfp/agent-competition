# CSV 中间格式 v1.0（P2 与全队的数据入口）

> 一句话：**队员各自的手表导出格式都不一样，但进入系统的只能是这一种 CSV。**
> 这个文件是 P2 解析器的输入契约，也是 P1 导出真实数据时要遵守的格式。
> 改动本文档 = 改契约，必须走 `docs/版本与标签.md` 的变更流程，并升级版本号。

- 适用：P2（写解析器）、P1（导出本人数据）、P5（做"导入"演示）
- 文件：`data/sample/activities_sample.csv`（脱敏样例）、`data/raw/*.csv`（真实数据，不进 Git）
- 解析器：`src/p2_ingest/csv_parser.py` → 输出 `activity.json`（符合 `contracts/activity.schema.json`）

## 一、为什么要有中间格式

| 来源 | 各自的不一样 |
|---|---|
| Garmin | 一活动一行、距离用 km、配速用 mm:ss、心率带小数 |
| 华为 / 高驰 | 中文表头、时间带时区后缀、有时一条记录拆多段 |
| Keep | 只有摘要没有逐公里、心率缺失时写 0 |
| 手动记录 | Excel 另存 CSV，容易带 BOM、数字变文本 |

如果不统一，P3 就会收到十种口径的数字，算出来的 ACWR 互相打架。所以规则是：
**原始导出放 `data/raw/` 一个都不进版本库，P2 负责把它转成本格式，之后全队只见中间格式。**

## 二、列定义

| 列名 | 类型 | 单位 | 必填 | 缺失时怎么写 | 示例 |
|---|---|---|---|---|---|
| `date` | 字符串 | — | 是 | 不能缺失，缺失整行丢弃 | `2026-11-12` |
| `start_time` | 字符串 | — | 否 | 留空 = null | `06:30` |
| `sport` | 枚举 | — | 是 | 中文可写，解析器负责映射 | `run` / `跑步` |
| `duration_s` | 整数 | 秒 | 是 | 不能缺失（可估算但必须在备注说明） | `2880` |
| `distance_m` | 小数 | 米 | 是 | 跑步类不能缺失；力量课写 0 | `8000` |
| `avg_hr` | 整数 | bpm | 是 | 没戴心率带写空 → 整行丢弃（不猜） | `152` |
| `max_hr` | 整数 | bpm | 是 | 同上 | `171` |
| `elevation_gain_m` | 小数 | 米 | 否 | 留空 = null | `22` |
| `avg_pace_s_per_km` | 小数 | 秒/公里 | 否 | 留空则由解析器按 `duration_s / distance_m` 计算 | `360` |
| `rpe` | 整数 | 1–10 | 否 | 留空 = null（不许填 0） | `6` |
| `sleep_h` | 小数 | 小时 | 否 | 留空 = null | `6.5` |
| `pain` | 字符串 | — | 否 | 无疼痛留空；有疼痛写部位+感觉 | `右膝外侧跑后酸` |
| `source` | 枚举 | — | 否 | 留空默认 `csv` | `garmin` |

**sport 允许值**：`run` `bike` `swim` `strength` `other`（中文映射：跑步→run、骑行/自行车→bike、游泳→swim、力量/力量训练→strength、走/徒步/其他→other）

## 三、五条硬规则

1. **编码 UTF-8 无 BOM**。Excel 另存会加 BOM，解析器用 `utf-8-sig` 兜底，但导出时请存成「CSV UTF-8」并把 BOM 去掉。
2. **换行 LF**，逗号分隔，字段内需要逗号就用双引号包起来。
3. **一行 = 一次活动**。一段跑分多条记录的，先在原始数据里合并，或按多条活动录入（各自有 date）。
4. **缺失一律留空**，不许写 `0`、`-`、`N/A`、`无`。心率写 0 会把均值拉垮——这是本项目最贵的坑。
5. **时间用本地时间**（Asia/Shanghai），跨零点跑步按**开始时间**归属日期。

## 四、从各家导出到这里怎么转

| 来源 | 转换动作 |
|---|---|
| Garmin Connect | 导出 CSV 后：`距离(km) × 1000` → `distance_m`；`时间` 拆成 `duration_s`；`平均配速` 保留原值即可，解析器会自算 |
| 华为运动健康 | 表头中文化，`运动类型` 按映射表翻成 `sport`，`时长` 常为 `hh:mm:ss`，需换算成秒 |
| 高驰 COROS | 导出含「训练负荷」列，本项目不用；只取时间/距离/心率三列 + 主观 RPE 手动补 |
| Keep | 只有摘要，缺心率时按规则留空（该行会被丢弃），建议同时补一次手动记录 |
| 手动 | 用 `data/sample/activities_sample.csv` 复制表头再填，别自己造列 |

## 五、验收标准（P2 完成这步才算交付）

```bash
python src/p2_ingest/csv_parser.py data/sample/activities_sample.csv -o out/activity.json
python contracts/validate_contract.py out/activity.json     # 必须 PASS
python tools/check_rules.py                                 # 顺带查规则库
```

样例文件的预期结果：**2 条入库、1 条因缺时长丢弃、1 条心率异常（avg 210 > max 175）旁路写入 `out/rejected.json`。**

设备异常行按 R02 处理：**不进主数据**（否则 C2 跨字段校验会失败），但也不静默消失——写进 `out/rejected.json`，报告里要能说明「哪几条被判为设备问题、为什么」。
