# V2.8 · 通俗显示 + 专业分析弹窗

基础跑步数据和完整训练报告仍然使用通俗中文。每张跑步指标卡片，以及趋势、负荷、风险、训练计划、训练报告的对应章节，都有「专业分析」按钮。点击后的小窗口显示本次报告实际计算的技术指标、解释、条件和规则依据；没有值显示「未计算」。

- `professional_analysis.js`：模块化专业数据展示与 `<dialog>` 交互，统一使用文本节点插入，不处理用户数据为 HTML。
- `professional_analysis.css`：弹窗、按钮、手机与减少动画样式。
- `training_review.js`：完整报告的主要内容以跑步概况、恢复与建议为主，导出独立 HTML 时将专业按钮转成可折叠的技术详情。
- `dashboard.js`：首页各指标的独立按钮，并在每次加载/生成报告后刷新专业窗口的数据源。
- `server_app.html`：正式页面入口，通过 `/live` 使用。
- `index.html`：不联网也能双击打开的匿名示例预览。

更多请看 `docs/RunWise-V2.8-专业分析分层显示-操作说明.md`。

# RunWise AI V2 · 本机网页版操作说明

> 所有指标、训练计划、风险信号、自检结果来自原项目的 P2/P3/P4 规则引擎与 v2 报告契约，不是浏览器随机生成的假数据。静态页面不代替服务端计算。

## 启动前准备

- Windows：双击项目根目录的 `一键启动-RunWiseAI.bat`，自动启动服务并打开浏览器。
- macOS / Linux：在终端执行 `sh ./一键启动-RunWiseAI.sh`。
- 或在项目根目录执行：`python -m src.pipeline --demo --serve`，然后手动打开 `http://127.0.0.1:8080/live`。
- 建议 Python 3.12；这次交付同时使用 Python 3.13 做了运行测试，项目原始要求仍以 Python 3.12 为准。无需 npm / Node.js、无需联网。
- 停止：在运行 Python 的终端按 `Ctrl+C`。若 8080 端口被占用，命令行可使用 `--port 8090` 并访问对应端口；一键启动器固定 8080。

**免安装快速看界面**：直接双击项目根目录的 `RunWiseAI-纯离线交互预览.html`。该文件预置脱敏演示数据，可浏览图表和点击训练日，但没有 CSV 导入、历史查询、AI 请求或后端重新校验。完整功能仍须启动 Python。

## 新版页面操作

1. **快速演示**有三种：草案生成 / 人工复核 / 数据不足。选择草案可看到 7 天卡片和 R19/R20 失败→重排→通过的完整过程；人工复核展示停止排课；数据不足展示待补信息。每次运行都真正走完整本地流水线并生成文件。
2. **数据图表**可切换 7 天、28 天、全部，鼠标移动查看当天 TRIMP；键盘聚焦图表后用左右方向键查看数据点。`null` 数据不被当作零。
3. **训练计划**点击任一天，侧边抽屉会展示距离、时长、TRIMP、参考心率及规则来源。点击“调整训练日期”，选择两个日期交换；后端重新执行 R19/R20 和报告 Schema 校验，成功后保存一份新报告。**这仅是日期互换与两项规则复核，不等于对新的疼痛、天气或当前生理状态做了实时全量重评，必须人工确认。**
4. **风险与依据 / 数据可信度**：展开规则条目阅读条款、出处和建议。质量模块展示原始缺失/异常标志，导入后还显示活动行数。
5. **CSV 导入**：上传或拖拽 2 MB 内 CSV，第二步预览表头与最多 5 行，第三步填写心率、TRIMP、日期等参数。格式支持中间格式、Garmin、华为及自动识别。预览行数只是粗略估算，最终校验完全由后端负责。补充量测/上下文 JSON 的单文件上限 256 KB。
6. **AI 解读（可选）**：点击“配置 API 连接”，输入可用 HTTPS API、模型名和密钥。默认仅点击“连接并分析”才请求模型；只有主动勾选“报告更新时自动分析”，后续更新才再次调用。API 服务可能收费，自动请求可以关闭。密钥只保留在当前标签内存，不写入历史和导出文件。AI 不参与本地规则与计划生成。连接分析完成后可使用“针对本次报告追问一句”进行单轮问答；每次由用户主动发送，均可能产生 API 费用。
7. **历史记录**：每次成功生成报告存放于 `out/pipeline/run-*/`。页面支持打开历史报告（只读）或与当前已加载报告的三项指标对比。不会上传云端。**历史对比窗口可能不同，请自行核实时间范围。**
8. **导出**：右上角可下载独立 HTML 报告、原始报告 JSON、逐日 TRIMP CSV 或使用浏览器打印保存为 PDF。独立 HTML 在不运行 Python、没有网络的电脑或手机上也能打开，**仅供只读查看，不支持重算**。不要公开分享含真实训练数据的报告。
9. **主题、手机、PWA**：页面支持深浅色切换、手机底部导航、减少动态效果偏好。Chrome / Edge 可尝试安装为 PWA。PWA 缓存的只是 HTML/CSS/JS 图标等**公开壳资源**，不会缓存真实报告、CSV 或密钥；关闭 Python 服务后，仍需运行服务才能重新计算或查看 API 报告。手机不直接连接电脑的 `127.0.0.1`，要跨设备分享请使用 HTML 导出或自行部署带访问控制的服务。

## 隐私和安全边界

- 服务仍只监听 `127.0.0.1`，服务端验证 Host 和 POST Origin；不对外网公开。
- 服务端历史接口只读取校验通过的 `run-*` 文件夹下报告；交换日程后仍要通过 R19/R20 与 v2 JSON Schema；失败保留旧计划。
- 跑步、心率、恢复指标属于敏感个人资料。勿把真实数据连同源码、生成的 `out/` 报告上传公共仓库。
- 规则信号不构成医学诊断；训练草案需本人或教练复核。包含伤痛等复核信号时不自动排课。

## 接口列表

| 路径 | 功能 |
|---|---|
| `GET /api/health` | 本机服务状态 |
| `GET /api/snapshot` | 当前校验通过的报告 + 导入质量 + 报告 ID |
| `POST /api/run` | `demo` / `review` / `missing` / `csv` 全流程 |
| `GET /api/history` | 已验证的历史报告摘要，最多 18 条 |
| `GET /api/history/run-*` | 历史报告详情，只读 |
| `POST /api/replan` | 两个日期交换，服务端 R19/R20 + 契约验证后发布 |
| `POST /api/ai` | 可选外部模型文本解读 |
| `POST /api/ask` | 可选单轮报告追问，严格基于脱敏报告摘要 |
| `GET /sample.csv` | 固定脱敏演示 CSV |
