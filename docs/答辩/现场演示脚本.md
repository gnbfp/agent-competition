# 现场演示脚本

演示约 4 分钟，预留 1 分钟给开场与切换。使用项目随附的模拟数据，演示前打开本机页面。

```powershell
python -m src.pipeline --demo --serve --port 0
```

| 时间 | 操作 | 口播与屏幕核对 |
|---|---|---|
| 0:00–0:35 | 点击「运行草案演示」。移动到「训练负荷趋势」 | “我们把手表记录转换成逐日训练负荷。确认没有训练的日期显示零，数据不足的日期留空。” |
| 0:35–1:30 | 查看下周 7 天安排。展开「查看计划自检记录」 | “首轮计划因为总负荷超过项目上限、还有一天缺少适用依据而被打回。重排后，第二轮 R19 和 R20 都通过，草案交本人或教练确认。” |
| 1:30–2:20 | 点「运行复核演示」，在「信号与依据」展开 R15 | “这份模拟案例有需要复核的疼痛信息。页面保留规则原文和出处，并暂停排课。” |
| 2:20–3:35 | 导入模拟 CSV。回答「请确认目前是否有疼痛」为「是」，点击「提交答复并复算」 | “系统会确认缺少的信息。提交模拟答复后，报告从待补数据切换到人工复核，可以展开 R15 查看原因。” |
| 3:35–4:00 | 并排指向导入体检、规则出处和下周安排状态 | “导入质量、计算结果和决策依据都能核对。今天展示的三条路径只访问本机服务。” |

手工导入时选 `data/sample/huawei_export_sample.csv`，截止日填 `2026-11-17`，静息心率填 `55`，个人最大心率填 `190`，选择「女性系数」。来源保留「自动识别」，历史起始日和补充文件留空。页面应先显示「待补数据」。

如果服务端口有冲突，用带 `--port 0` 的命令重启，打开新打印的地址。如果时间只够展示两步，先演草案重排，再演 R15 复核。浏览器无法使用时，运行 `python -m src.pipeline --demo` 打开终端打印的报告，用[草案截图](../images/p5-offline-demo.png)说明两轮自检。
