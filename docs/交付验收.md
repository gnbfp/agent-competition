# 离线原型 v1.0 交付验收

程序基线为 `84ac882`。准备 Python 3.12.x 和现代浏览器，将交付包解压到新目录，多人可各自使用一份。项目使用 Python 标准库，演示可在断网环境运行。

## 启动

在解压后的项目根目录运行下列命令。Windows 上可用 `py -3.12` 代替 `python`，并用 `python --version` 核对当前解释器。

```powershell
python -m src.pipeline --demo --serve
```

浏览器打开终端打印的本机地址。初次打开为人工复核案例。点击「运行草案演示」可生成七天草案；点击「运行复核演示」可切回带 R15 依据的案例。按 Ctrl+C 停止服务。8080 端口被占用时，加 `--port 0` 让程序自动选择本机端口。

## 验收

安装 Git 2.40 或更高版本用于环境自检。在根目录依次运行下列命令。

```powershell
python tools/check_env.py
python tools/check_rules.py
python contracts/validate_contract.py
python -m unittest discover -s tests
python -m compileall -q src
```

对照预期结果检查。

| 项目 | 预期 |
|---|---|
| 环境检查 | 8 项通过 |
| 规则库 | 20 条规则完整，校验无失败。静态样例的规则引用覆盖范围会有提示 |
| 契约和回归 | 7 份契约样例、96 项单测通过 |
| 草案场景 | 28 天负荷图、7 天草案。展开自检记录，首轮 R19、R20 未通过，第二轮均通过 |
| 人工复核 | R15 可展开查看出处，周安排暂停 |
| 导入和追问 | 导入华为模拟 CSV 出现追问，提交模拟疼痛答复后切到人工复核 |
| 导入失败 | 坏文件得到明确提示，最近一份成功报告仍可查看 |

只生成文件时运行 `python -m src.pipeline --demo`。终端会打印本次 `report.json` 的位置，同目录有 `activity.json`、`metrics.json`、`plan.json` 和导入体检。将四份 JSON 路径传给 `python contracts/validate_contract.py` 可单独校验。
